01

Problem Identification

CHD Mortality

Congenital Heart Disease affects 8–12 per 1,000 live births globally, remaining the leading cause of neonatal mortality in low-resource settings

Data Silos

Patient data cannot be shared across hospitals due to HIPAA and GDPR regulations, preventing centralized multimodal learning

Modality Mismatch

Each hospital uses a different diagnostic modality (PCG, ECG, Echo), making standard federated learning with weight averaging impossible

Research Gap

Existing FL methods (FedAvg, FedProx) assume homogeneous architectures. Even FedProto assumes same data domain. The setting where each client has an exclusively different modality with no overlap remains underexplored.

Significance of the Project

01

Privacy-Preserving Collaboration

Only 512 bytes/round (2 prototype vectors × 64 floats × 4 bytes) are transmitted — an 87,800× reduction compared to FedAvg. No raw patient data or model weights ever leave the hospital.

02

Cross-Modal Knowledge Transfer

For the first time in pediatric cardiology, hospitals with entirely different modalities can share diagnostic knowledge through a shared prototype space, without needing paired patient data.

03

Low-Resource Clinical Impact

Rural clinics with only a $50 digital stethoscope can benefit from the diagnostic knowledge of an advanced echo center, potentially improving CHD detection in underserved communities.

04

Scalable & Modular

The prototype-based approach is model-agnostic — new hospitals with new modalities (e.g., cardiac MRI) can join the federation without requiring any existing participant to change their model.

Methodology — Training Protocol

R0

Local Warmup (Round 0)

Train each client independently for 5 epochs using cross-entropy loss only. No prototype exchange yet — models learn basic modality-specific features.

P

Prototype Initialization

Each model computes 128-d embeddings → projects via gk to 64-d → computes class centroids (mean embedding for Normal, mean for Abnormal). Server aggregates into global prototypes.

FL

Federated Training (Rounds 1–N)

Each round: 5 local epochs with combined loss → compute prototypes → server aggregation → broadcast. Early stopping after 8 rounds of no improvement.

Total Loss: ℒtotal = ℒCE + 0.5 · ℒproto + 0.05 · ℒcontrast
ℒCE
Cross-Entropy

Standard classification loss with class weighting

ℒproto
Prototype Alignment

L2 distance: pulls embeddings toward global class prototypes

ℒcontrast
Contrastive

InfoNCE: pushes apart different-class prototypes, prevents collapse

Objectives and Scope

🎯 Core Objectives

1
Cross-Modality Knowledge Exchange

Enable 3 hospitals with genuinely different modalities (PCG, ECG, Echo) to share diagnostic knowledge via lightweight class-prototype alignment — the primary research contribution.

2
Same-Architecture Sanity Check

Validate FedAvg/FedProx on 9-lead vs 12-lead ECG split as a positive control before trusting cross-modal aggregation.

📋 Scope

✅ In Scope

  • Binary screening: Normal vs Abnormal
  • 3 real public datasets, no synthetic data
  • Prototype-based federation (no weight sharing)
  • Privacy analysis (512 bytes/round)
  • Comparison vs solo baselines
  • Ablation study of loss components

❌ Out of Scope

  • Formal differential privacy (DP-SGD)
  • Real multi-hospital deployment
  • Multi-class CHD diagnosis
  • 3D video transformers for Echo
  • Secure aggregation protocols
  • Prospective clinical validation

Conclusion & Future Work

✅ Key Contributions

  • Proposed CrossFedProto — cross-modal federated prototype learning enabling hospitals with entirely different modalities to collaborate
  • ECG AUROC improved by +1.33%; PCG sensitivity improved by +6.84% — demonstrating successful cross-modal knowledge transfer
  • Prototype cosine distance reduced from ~1.06 to <0.001 — modality-specific features translated into a unified semantic space
  • Communication reduced to 512 bytes/round — an 87,800× reduction vs FedAvg

🔮 Future Work

  • Extend to multi-class CHD diagnosis with hierarchical prototype structures
  • Integrate formal differential privacy guarantees (DP-FedProto)
  • Validate on paired multimodal datasets (e.g., MIMIC-IV-ECG with clinical notes)
  • Prospective multi-hospital pilot for clinical validation
  • Add new modalities (cardiac MRI, continuous monitoring) without modifying existing clients
